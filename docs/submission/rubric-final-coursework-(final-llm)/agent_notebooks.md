## 2. Execution Path

```text
Local Jupyter notebook
  -> kubectl port-forward service/kagent-controller
  -> JSON-RPC SendMessage to /api/a2a-sandboxes/kagent/<agent>/
  -> kagent SandboxAgent on a Substrate worker pool
  -> RemoteMCPServer bound to the SandboxAgent
  -> MCP function
  -> downstream recommendation or RAG service
  -> function_response recorded in A2A history
```

The `chat()` cell in each notebook performs only three operations: it opens a temporary port-forward, sends `message/send` with a `messageId` and `contextId`, and returns the raw response through `json.load(response)`. The experiment cell calls `chat(...)` and displays `result` directly.

## 3. Reading the MCP Evidence

`status.state: completed` indicates only that the A2A task has finished. Direct evidence of MCP function execution is the pair of events in `result.history`:

1. A data part with `metadata.adk_type: function_call`, containing the tool name, arguments, and tool-call ID.
2. A data part with `metadata.adk_type: function_response`, containing the same tool name and tool-call ID together with the output or error returned by MCP.

Matching the tool-call ID between the request and response distinguishes function output from presentation text generated by the model.

## 4. Experiment 1: Personalized Recommendations

The notebook asks `recsys-recommendation-agent-sandbox` to recommend three products for user `1001`.

The recorded output shows the agent issuing this call:

```text
adk_type: function_call
name: get_personalized_recommendations
args: {user_id: 1001, candidate_item_ids: None, top_k: 3}
tool-call id: m2tl7GdRVXjCV34Xis4j9M8XgFWv1qQX
```

MCP returns a response with the same ID:

```text
adk_type: function_response
name: get_personalized_recommendations
items: [800075, 800145, 800015]
model_version: 20260823155004
```

This historical result demonstrates that the agent did not generate the recommendations directly with the LLM. The item IDs, scores, and model version appear in the `function_response` before the agent produces its presentation text. The captured final text is truncated at `candidatesTokenCount=256`, but the raw tool response contains all three items, so MCP execution completed successfully. The live ModelConfig now permits 384 output tokens.

## 5. Experiment 2: Grounded RAG Context

The notebook asks `recsys-context-agent-sandbox` to execute `retrieve_rag_context` for the query `noise-cancelling headphones` with `top_k_items=1`.

The raw history records two attempts:

- The first attempt issues a `function_call` without arguments and receives a validation-error `function_response` because `query` is missing.
- The agent corrects the request, issues a `function_call` with `query`, `top_k_items=1`, and `filters=None`, and then receives a successful `function_response` with the same tool-call ID, `dFa5pTGmepXgkTDNSLaI3oCOq4hwNCMF`.

The successful response contains:

```text
item_id: 800059
pipeline_run_id: rag-pipeline-fallback96-20260823
first chunk_id: 800059:product_overview:overview:0
```

This experiment confirms that the MCP and RAG backend execution path works. It also records that the model did not fully satisfy the “exactly once” constraint: it generated one invalid call and then retried successfully. This is a tool-call generation issue to improve, not a connectivity failure or an MCP function failure after valid arguments were received.
